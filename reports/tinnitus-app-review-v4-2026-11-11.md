## 2. Bugs users will hit

- **Trigger Impact names a direction at 60% even when the 95% interval crosses zero.** `prob >= 0.6 ? probWorse/probBetter` never looks at `ciLow/ciHigh`; with se = 0.4 and effect 0.6, P = 0.60 and the interval is −0.18…+1.38. The suffix labels on the same panel correctly require `ciLow > 0`, so the panel shows "−0.2 to +1.4 levels" (no direction) and under it "60% likely to be meaningfully worse". The guide promises the opposite in 28 languages (`guides/en.ts:34`), the PDF repeats the logic (`reportHtml.ts:119-120`), `evaluate.ts:79-81` claims 0.9. `app/(tabs)/trends.tsx:322-337` (A60/A82, open since v2)
- **iOS: the date/time picker in the entry form can never be dismissed.** `setShowDatePicker(Platform.OS === 'ios')` keeps it mounted, inline between the header and the ScrollView, no Done. `ReminderPromptHost.tsx:89-94` already uses `display="compact"` — reuse it. `app/components/EntryForm.tsx:462-481` (A51)
- **Leaving a partly filled entry loses it silently.** Header back, hardware back and iOS swipe all call `router.back()` with no dirty check; a long note is gone with one gesture. Same for Cancel/back on `ManageItemsScreen.tsx:194` and `SingleChoiceScreen.tsx:147` with pending changes. `EntryForm.tsx:289, 294-300, 416` (A168, A67 remainder)
- **Deleting an entry leaves orphan join rows.** `PRAGMA foreign_keys` is never set (the only PRAGMA is `table_info`, `database.ts:112`), `deleteEntry` deletes from `entries` only. The orphans are counted by `COUNT(ett.entry_id)` on the Manage screens and by the guard in `deleteTrigger`/`deleteTinnitusType`, so a custom trigger used only on a deleted entry can never be deleted. `deleteAllEntries` is four autocommit statements with no transaction. `app/db/queries.ts:309-311`, `:573-578` (A41–43)
- **Re-importing the same backup doubles the diary.** `importEntries` inserts every validated row with no existence check (`created_at` is unique in practice thanks to milliseconds). `queries.ts:489-539` (Council #6, A62–64)
- **Import can disable a built-in trigger via a case-insensitive collision.** The `typeIdByName`/`triggerIdByName` maps are exact-match while `addCustom*` looks up `COLLATE NOCASE` and returns the existing id; a backup with custom "stress" `is_active:false` on a device with built-in "Stress" passes `has()` (false), gets the built-in's id and `setTriggerActive(id, false)` switches it off. `queries.ts:122-128, 496-507` (S21)
- **Startup has no safety net.** `try { initDatabase() … } finally { setAppReady(true) }` with no `catch`; no ErrorBoundary; `openDatabaseSync` runs at module import (`database.ts:4`). A migration failure = crash behind the splash with no report. `app/_layout.tsx:162-175` (A36/A103)
- **Reminders: enabling schedules before permission and never re-syncs after a grant.** `toggleEnabled` → `refreshAndSync()` → `syncReminderNotifications()` and only then `requestPermissionForReminder()`, which does nothing after `granted`. On iOS a request before authorization is rejected (`notificationsNotAllowed`), so after Allow nothing is scheduled until the next cold start. `handleBannerPress` and `ReminderPromptHost.accept` do it right. `app/reminders.tsx:76-83, 101-107` (A173 remainder, S22)
- **Overlapping `syncReminderNotifications` calls can double-schedule** (cancel-all A, cancel-all B, schedule A, schedule B → every reminder twice). No serialisation; un-awaited callers in `reminders.tsx:98`, `ReminderPromptHost.tsx:65`, `_layout.tsx:170`. `notifications.ts:155-177` (A111/A112 — reported fixed on 27 Oct, the code read today has no serialisation)
- **The reminder soft ask burns one of its two lifetime asks even when nobody saw it.** `markReminderPromptShown()` + `reminder_prompt_shown` run in a `setTimeout` regardless of `suppressed` (App Lock). `ReminderPromptHost.tsx:41-50` (S23)
- **`report_created` and the "first_report" milestone fire on cancel.** `logEvent` sits outside `if (saved)`; the SAF picker returns `null` and the event still logs; `createAndShareReport` returns `true` as soon as `shareAsync` resolves. `app/reports.tsx:84, 104`, `reportExport.ts:22-34, 55` (S5)
- **The Home greeting goes stale.** `useMemo(() => greeting(t), [t])` — Home stays mounted for the app's lifetime, "Good morning" lasts into the evening. `app/(tabs)/index.tsx:123` (A101/A162)
- **Stats keeps yesterday's window past midnight** (the fingerprint tracks diary content only; `filterItems` reads `new Date()` inside a memo) and **"All" is still capped at 1,000 entries**, Home at 200. `trends.tsx:1596-1609`, `index.tsx:107, 117` (A32–35)
- **The 90D chart covers up to 91 days while the tiles filter 90.** 13 Monday-anchored weeks vs a cut at 89. `sevenDayTrend.ts:58-65, 139-148` (S24)
- **Stats memoisation is defeated every render.** `t('stats.dowLabels', { returnObjects: true })` returns a new array per call (verified on i18next 26.3.6), `distressLabels` is a literal; both are deps of 13 memos, so opening a panel or toggling bars/line reruns the whole pipeline and fresh `buckets` reset chart selection (tap-to-inspect labels vanish). `trends.tsx:1611-1615, 1661-1676` (A83)
- **By Day of Week ignores First Day of Week** (Monday hard-coded, `trends.tsx:865-875`; 90D weekly buckets too, `sevenDayTrend.ts:139-143`), while Calendar, Month Glance and Widgets rotate by the setting. (A164)
- **"Not enough data for this period yet" is impossible to satisfy on 7D** (`MIN_OBSERVATIONS = 8`, 7D has at most 7 days) and the default "Effect" sort silently falls back to count. `triggerModel.ts:91, 158`, `trends.tsx:520, 743, 830` (A163)
- **iOS export leaves the unencrypted backup in cache and records "exported" on cancel**; the imported JSON (health data) stays in cache forever (`copyToCacheDirectory: true`, never deleted). `app/my-data.tsx:257-268`, `:292-298` (A52/A158, S25)
- **Hardware Back on the locked app drives the navigator under the overlay.** `LockScreen.tsx` has no `BackHandler` (the only one is `EntryForm.tsx:294`). (S12)
- **Delete All Data does not reset Firebase Analytics** (`resetAnalyticsData` never called) and **screen views log the raw path including entry ids** (`/entry/42`). `my-data.tsx:351-368`, `_layout.tsx:116` (S13, A150)
- **RevenueCat ↔ Firebase link** runs in `initPurchases()` before `applyUsageConsent()` and never re-runs after consent is granted in-session. Effectively gated today only because Firebase returns no id while native collection is off; its purpose ("attribute purchase events in Firebase Analytics") is exactly what the user may decline. `purchases.ts:29, 36-40`, `_layout.tsx:157, 166` (S10, partly)
- **A malformed deep link throws inside the router.** `decodeURIComponent` without try/catch in `widgetLinks.ts:32`; `tinnitus-app://widget?action=%` (public scheme, any app or `adb`) → `URIError` in `redirectSystemPath`. (S26)
- Smaller: reminder text is frozen in the language active at scheduling time (`notifications.ts:163-164`, A146); hardware back during the 200 ms after Save → double pop (`EntryForm.tsx:405-406`); prev/next month in the Calendar auto-selects the 1st (`calendar.tsx:180, 189`); on iOS every Pro gate pushes `/paywall` and pops immediately with no message (`paywall.tsx:52-57`); `openNotificationSettings()` opens App Info on Android, not the notification page, and suppresses App Lock for a genuinely external screen (`notifications.ts:47-68`, S32); several promises without `.catch` (`_layout.tsx:169-171`, `AppLockContext.tsx:33, 63`, `entry/new.tsx:42`).

## 4. Design decisions worth revisiting

- **The Calendar shows a day's maximum, the charts its mean** (entries 1 and 5 = red 5 on the calendar, orange 3 on the chart); nothing explains it. The count badge already signals multiple entries; a "highest level of the day" hint is enough. `calendar.tsx:275-277` vs `sevenDayTrend.ts:278-283` (A137)
- **The "Change" tile is 20 × levels as a percentage** ("+20%" for one level) while the trigger panel uses levels — two units for one quantity on one screen. `sevenDayTrend.ts:339-344` (S33)
- **PDF "coverage"** has a different denominator per range (30D/90D fixed 30/90 days, All = first…last entry), undefined in the PDF. `reportData.ts:121-135` (A142)
- **The PDF trend line spaces days evenly by index**, not by date — a three-week gap is one step, and there is no x-axis. `reportHtml.ts:26-30` (S34)
- **Soft ask: backdrop tap / Android back counts as a decline** (`ReminderPromptHost.tsx:84 onDismiss={decline}`), consuming one of two asks.
- **Level names differ between app and PDF**: `entryForm.intensityLevels[1]` "Barely noticeable" vs `reports.pdf.levels[1]` "Faint".
- **"Average location/pitch/distress broken down by day"** for categorical data — it is a composition (share), not an average. `en.json:83-85` (S38)
- `userInterfaceStyle: "light"` (A28, iOS never dark on Automatic) and `supportsTablet: true` without tablet layouts (A136) are still in `app.json:9, 11`.
